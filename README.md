# 出大事行事曆

兩個人共用的行事曆：一個人先排活動，另一個人「確認」或「再議」，每個活動都有備註和留言紀錄。

```
index.html（GitHub Pages）  ──POST──▶  GAS 網頁應用程式（gas/Code.js）  ──▶  Google 試算表「出大事行事曆」
```

## 怎麼用

- **手機**：列表模式，從這週一起列 90 天（`LIST_DAYS`），依活動排：只列有活動的日子（左邊日期、右邊活動），換月有月份標題，多天的活動只出現一次；今天沒活動會畫一條「今天」的線。點左邊的日期可以在那天新增
- **平板、電腦**（寬度 768 以上）：右上角切「列表／三週／月」，會記住上次選的
- 🔧 第一次用：點試算表「設定」分頁的**秘密連結**（`…/MyCalendar/#k=鑰匙`），再選「我是誰」。同一支手機之後都會記住，不用輸入任何東西；右上角可以換身分
- 沒用秘密連結打開（只打 `tjc-km.github.io/MyCalendar`）會看到「請用秘密連結打開」，讀不到也改不了資料
- 手機的瀏覽資料被清掉、換手機、或用「加到主畫面」的圖示打不開時：再點一次秘密連結就好，所以連結要留在 LINE 對話裡
- 頂部的 🔔「N 件等你回覆」是最重要的：對方排的活動等你確認，或你排的被對方說再議
- 按下確認、儲存，畫面馬上就變，GAS 在背景存（大約 2～3 秒）；那一筆會淡一點、寫「儲存中…」，存好之前不能再改它。存失敗（例如對方剛好改了同一筆）會還原、跳紅字並重新整理。還在存的時候關掉頁面，瀏覽器會先問一聲
- 新增活動：時段選「整天／上午／下午／晚上」就好；要準確時間按「⏱ 設定準確時間」才會出現。填了準確時間，時段自動跟著選；改選別的時段會清掉準確時間。新增畫面沒有地點欄（2026-11-20 使用者定），舊活動的地點保留、照樣顯示
- 右上角「☑ 待辦」：兩個人共用的待辦清單，數字是還沒做的件數。最上面打字按新增；點方框打勾（再點一次改回還沒做）；點文字可以改負責的人、期限，或刪除。待辦不用對方確認

### 待辦的規則

- 新增時負責人預設「兩人」、沒有期限；要改就點文字進去改
- 還沒做的照期限排（過期的紅字），沒期限的排最後；做完的移到下面「做完了」，只顯示最近 30 天內完成的（`TASK_DONE_KEEP_DAYS`，更早的還在試算表裡，只是不顯示）
- 🚨 刪除是真的刪掉試算表那一列，找不回來；只是做完的話打勾就好

### 為什麼用秘密連結

repo 必須公開才能用免費的 GitHub Pages，網頁原始碼（含 GAS 網址）任何人都看得到。所以改成：GAS 每次都檢查鑰匙，鑰匙只存在試算表（私人）與兩支手機裡，不進 repo。`#` 後面的部分瀏覽器不會送給 GitHub，只有手機自己讀得到。使用者不要每次輸入通關密語（2026-11-20 決定）。

### 為什麼存檔要等

GAS 每次請求光開機就要 1 秒左右（一陣子沒人用之後的第一下會更久），再加上讀寫試算表，存一次大約 2～3 秒。所以畫面不等 GAS，先照預期改好；「設定」分頁也記在 GAS 的快取裡，省掉每次開試算表（2026-11-20 實測：輕量請求從 1.6～2.2 秒降到 1.0～1.2 秒）。要再快只能換掉 GAS（例如 Cloudflare Worker），但資料就不在試算表了。

### 活動的狀態

| 狀態 | 意思 | 誰要動作 |
|---|---|---|
| ？ 待確認 | 有人新增或改了內容 | 另一個人：確認或再議 |
| ✓ 已確認 | 對方同意了 | 不用 |
| ！ 再議 | 對方覺得要調整 | 提出的人：修改內容，或「維持原案，再問一次」 |
| ✕ 已取消 | 任何一方取消 | 要的話可以「恢復」，恢復後又是待確認 |

- 改了**日期、時段、時間、標題、地點、參加**，會變回待確認，換另一個人確認（改的人就是新的提出人）
- 只改**備註**、只**留言**，狀態不變
- 每個動作（新增、修改了什麼、確認、再議、留言、取消）都會寫進「留言紀錄」
- 兩人同時改同一筆：後存的人會被擋下，畫面自動重新整理後再改一次，不會互相蓋掉

## 試算表

### 「活動」分頁

程式依表頭找欄位，欄位順序可以調；可以自己加欄位，存檔時不會被清掉。所有欄位都存成純文字。

| 欄位 | 內容 |
|---|---|
| ID | 自動產生，不要改 |
| 開始日期、結束日期 | `2026-11-20`；結束日期只有多天活動才不一樣 |
| 開始時間、結束時間 | `18:30`；可以空白 |
| 時段 | `上午`／`下午`／`晚上`，空白＝整天。有開始時間時程式依時間自動決定（12 點前上午、18 點前下午、之後晚上），手填的會被蓋掉 |
| 標題、地點、備註 | 地點畫面上已經不能填，只顯示舊資料 |
| 參加 | `兩人` 或其中一位的名字（決定顏色：紫＝兩人、藍＝成員1、粉紅＝成員2） |
| 狀態 | 待確認／已確認／再議／取消 |
| 提出人 | 最後一次新增或修改內容的人；另一個人負責確認 |
| 回覆人、回覆時間 | 誰在什麼時候確認或再議 |
| 建立人、建立時間 | |
| 修改時間 | 用來判斷「對方剛改過」，不要手動改 |
| 留言紀錄 | 一行一筆，最新的在最下面 |

直接在試算表加活動也可以：填 ID（隨便一串不重複的字）、開始日期、標題就好，狀態空白會當成待確認。

### 「待辦」分頁

| 欄位 | 內容 |
|---|---|
| ID | 自動產生，不要改 |
| 內容 | 待辦的文字 |
| 負責 | `兩人` 或其中一位的名字 |
| 期限 | `2026-11-28`，可以空白 |
| 完成 | 做完填 `Y`，沒做完空白 |
| 完成人、完成時間 | 誰在什麼時候打勾 |
| 建立人、建立時間、修改時間 | |

### 「設定」分頁

| 項目 | 沒設定／做錯會怎樣 |
|---|---|
| 成員1、成員2 | 兩個名字要不同、不能叫「兩人」，不然網頁會報錯。改名後舊活動的提出人、建立人還是舊名字，那些活動會變成兩邊都顯示「等你確認」，要手動把舊名字改掉 |
| 鑰匙 | setup 自動產生 32 碼。空白的話網頁完全不能用。🚨 改掉或清空再跑 setup，舊連結立刻失效，兩支手機都要點新的秘密連結 |
| 秘密連結 | setup 依鑰匙自動寫入，不用手動改。外流了就換鑰匙 |

🚨 直接在試算表改「設定」分頁（名字、鑰匙），**最多 5 分鐘後才生效**（GAS 的快取）。要立刻生效：改完在 GAS 編輯器執行一次 `setup`。

## 部署與維護

- GAS 專案「出大事行事曆」是獨立專案（不是從試算表開的），用試算表 ID 開檔
- 改 `gas/Code.js` 後：在 `gas/` 資料夾 `clasp push`，再 `clasp redeploy <部署 ID> --description "說明"`，**網址不變**。只 push 不 redeploy 的話，網頁用的還是舊版
- 🔧 第一次使用：在 GAS 編輯器選 `setup` 執行一次（會要求授權），它會把「工作表1」改成「活動」、建「待辦」「設定」分頁、產生鑰匙與秘密連結；可以重複執行，不會動到已有的資料，也不會換鑰匙
- 程式加了新欄位或新分頁（例如「時段」「待辦」）：GAS 讀資料時發現少了，會自動照 setup 的做法補上，不用手動執行 setup。補不上才會報「自動補不上：請在 GAS 編輯器執行一次 setup」
- `gas/.clasp.json`（含 GAS 專案 ID）不進 git，換電腦要重新 `clasp clone`
- 一週從週一開始；要改成週日，改 `index.html` 的 `WEEK_START = 0`

不用碰真的試算表：

```
node dev/test.js        # 測 GAS 的規則（26 項）
node dev/server.js      # 會印出本機測試用的秘密連結（每次啟動鑰匙都不同）；每個請求延遲 1.5 秒模擬 GAS，LATENCY=0 可關掉
```

`dev/fake-gas.js` 在 Node 裡載入真的 `gas/Code.js`，把試算表換成記憶體裡的假資料，關掉就沒了。`?api=` 只有在 localhost 才有效。
